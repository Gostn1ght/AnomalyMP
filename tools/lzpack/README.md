# Компрессор и обновления Lost Zone

Эта папка предназначена владельцу проекта. Игрокам передаётся только **Lost Zone**,
хостеру — **Lost Zone Server**. Не передавать им папку **Compressor**, особенно `private`.
Ключ из `private/lzpack-v1.key` нужен для выпуска будущих патчей. Не менять и не терять его:
тот же ключ хранится в секрете GitHub Actions `LZPACK_KEY_V1` и используется при сборке.

## Создать исправление

1. Создать отдельную папку, например `MyPatch`, и положить только изменённые файлы:
   - `MyPatch/gamedata/meshes/...`, `textures/...`, `sounds/...`, `levels/...` и другие ресурсы;
   - `MyPatch/client/scripts/имя.script` — скрипты игроков;
   - `MyPatch/server/scripts/имя.script` — серверные скрипты.
2. Открыть **Create patch.cmd**, указать папку и новый шестизначный номер, например `000001`.
   Можно перетащить папку на этот файл. Требуются Python 3 и пакет `cryptography`:
   `py -3 -m pip install cryptography==46.0.2`.
3. Готовые архивы `99_lz_patch_NNNNNN.db0` из `Patches/client` скопировать в `Lost Zone/resources`.
   Архивы из `Patches/server` — в `Lost Zone Server/resources`.
4. Перезапустить затронутый клиент или сервер после установки. Упаковщик ничего не запускает.

Все архивы игры лежат в одной папке `resources` и подключаются по имени: `00`–`90` — база,
`99_lz_patch_*` — патчи. Патч с большим номером заменяет совпадающий файл из базы или
более раннего патча.
Переупаковывать всю игру не требуется. Клиентский архив не содержит серверных скриптов.
Номер нельзя использовать повторно. Оригинальные базовые архивы остаются на месте.
Удаление файлов через архивные патчи пока не поддерживается: требуется отдельная миграция.
Исправления C++ требуют новой сборки GitHub Actions и замены соответствующих exe/библиотек.

Конфиги оставлены открытыми для совместимости: некоторые моды GAMMA читают/изменяют их
через обычный `io.open`, обходя файловую систему движка. Обновлять такие конфиги отдельно,
сохраняя настройки хостера. Сохранения, аккаунты, appdata, ключи и отладочные пробы в патч
включать нельзя — упаковщик отклоняет такие входные данные.

## Защита и сжатие

Базовые ресурсы уже сжаты `xrCompress`; шифрование сохраняет их сжатие. Маленькие новые
патчи собираются в стандартную внутреннюю таблицу X-Ray, затем шифруются AES-256-GCM.
При необходимости большой патч сначала сжимается штатным `xrCompress`, затем защищается:
`py -3 lzpack.py protect --key private/lzpack-v1.key --input patch.db0 --output protected.db0`.
Архив необходимо создавать с корректным `entry_point`, сохраняя порядок приоритетов.

Движок расшифровывает только нужные блоки по 64 КиБ, включая потоковое чтение звуков.
Он не распаковывает всю gamedata на диск или в память. Повреждение шифротекста, тегов,
заголовка и подмена порядка блоков отклоняются. Реализация использует
[аутентифицированное шифрование Windows CNG](https://learn.microsoft.com/en-us/windows/win32/api/bcrypt/ns-bcrypt-bcrypt_authenticated_cipher_mode_info).

Это защита от обычных распаковщиков, а не гарантия невозможности реверса: клиент получает
данные для игры и содержит необходимый материал ключа. Нельзя обещать абсолютную защиту
от извлечения из работающего клиента. В игре нет секретов администрирования сервера.

Оригинальные файлы после сборки сохраняются вне раздаваемых папок в `_work/retained_plain_*`.
Их не удалять до разрешённой проверки игры. Аккаунты и миры эта сборка не стирает.
