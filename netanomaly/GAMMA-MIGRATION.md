Подготовка в новый каталог:

```powershell
python netanomaly/tools/prepare_gamma.py --output netanomaly/generated/gamma-migration
```

Генератор выбирает реально выигрывающие scripts из overwrite, включённых модов
MO2 и базового gamedata. Создаёт отдельные экспериментальные профили клиента
и сервера, каталоги bin и отдельные appdata для процессов. Оригинальная установка
не изменяется. Для повторного запуска требуется новый каталог результата.

Это подготовка перехода, а не работающий мультиплеер. Поля требований в
`migration.json` не включают перечисленные механики. Отдельных собранных
GammaClientDX11.exe и GammaDedicated.exe пока нет. Старый AnomalyNetDX11AVX.exe

## Исправление сохранения и загрузки

Прежний Lua callback и патч меню разрешали сохранение и загрузку роли server.
Теперь обычное сохранение, загрузка, последнее сохранение и запуск новой игры
из меню блокируются для обеих ролей. В C++ патч добавлена блокировка команд
save/load/load_last_save и запуска start server(.../load). Сервер отклоняет
M_SAVE_GAME, M_SAVE_PACKET, M_LOAD_GAME и M_RELOAD_GAME в netcoop даже от
внутреннего хоста. Будущее серверное хранилище должно иметь отдельный путь.

Обновлённый подготовленный комплект: `netanomaly/generated/gamma-migration-savefix`.
Старые подготовленные комплекты не содержат этого исправления.

Сборка разрешена только через GitHub Actions, после переноса на GAMMA. Локальную
сборку больше не запускать. Сохранение игроков должно выполняться сервером по
идентификатору проверенного аккаунта: локация, положение, инвентарь с состоянием
предметов и боеприпасами, деньги, здоровье и индивидуальные задания. Вход игрока
восстанавливает его состояние, не загружая снимок всего одиночного мира.

## Административные команды

Команды сохранены. Патч закрывает CConsole::Show и пользовательский ввод до
получения серверного флага администратора. Скриптовые вызовы консоли допускают
локальные настройки отображения/звука; административные действия отправляются
серверу. Клиентская загрузка произвольного console script запрещена.

Сервер проверяет одноразовый билет аккаунта и fingerprint контента до создания
актора. Роль читается из атомарно обновляемого серверного account_roles при
получении команды, перед отложенным выполнением и в gamma_admin dispatcher.
Пароли radmins.ltx и первый автоматически назначенный администратор не используются.
Передача файлов обычным игроком отклоняется.

GAMMA debug launcher, прямые функции, методы спавнеров и Lua debugger widget
получают проверки прав. Меню отправляет серверу индекс действия; functor и его
параметры берутся из серверной таблицы. Lua выполняется в обработчике отложенных
пакетов, а не в сетевом callback. Игровая проверка этих изменений ещё требуется.
Редакторы, которым нужен игровой GUI/контекст host actor, пока не адаптированы
к будущему headless dedicated и индивидуальному административному актору.

## Сетевые обходы и контекст аккаунта

Клиентские пакеты разрешаются по списку допустимых типов. Подделка игровых
сообщений/снимков и импорт клиентских денег, статистики или флага администратора
через создание player state запрещены. Повторный handshake не заменяет player state.
Проверены границы encrypted wrapper; вложенные encrypted/event-pack обёртки
не допускаются, неверный checksum/seed отклоняется без VERIFY-аварии сервера.

Удалённые M_EVENT проходят проверку до receiver->OnEvent. Сейчас разрешён только
GE_INV_ACTION своего актора: точный размер, start/stop и оружейные key IDs.
GE_MONEY, healing, hit/die/destroy, teleport, ownership/trade, upgrades и visual
изменения принимает только внутренний сервер. Это закрывает прежние обходы,
но подбор, торговля, использование предметов и прочие операции ещё нуждаются
в отдельных проверяемых запросах: нельзя считать игровой процесс перенесённым.

Движение ограничено серверным временем, запасом 3 метра и скоростью 15 м/с;
physics position должен соответствовать base position, скорость physics ограничена.
Эти предварительные пределы ещё не проверены на GAMMA. Полная серверная физика,
navmesh-проверка и серверный расчёт попаданий пока не реализованы.

Native gamma_admin_actor выбирает actor по аутентифицированному peer, не по nickname.
money/spawn используют этот actor; item spawn оставляет владельцем предмета сервер.
Lua debug вызовы временно получают db.actor этого аккаунта с восстановлением даже
после ошибки. Отсутствующий actor не заменяется внутренним хостом. Это не исправляет
все ранее закешированные ссылки SP-модулей; редакторы/кеши требуют дальнейшей адаптации.
Имя отправителя чата берётся сервером; границы входного сообщения проверяются.

## ALife вокруг нескольких игроков

Патч заменяет пять проверок расстояния до story actor в переключении online/offline
для одиночных объектов, групп и online/offline squads. gamma_alife_distance собирает
позиции только подключённых аутентифицированных человеческих акторов сервера.
Близость к любому игроку удерживает NPC online; отсутствие игроков не подставляет
позицию внутреннего хоста. Story actor registry пока сохраняется для зависимостей SP.
Эта часть ещё требует сборки движка, проверки NPC в игре и нагрузки 128 игроков.

Оружейный ввод на сервере вызывает inventory.Action напрямую: штатный IR handler
отбрасывает Remote() актора и поэтому не выполнял пересланный ввод. Исправлен тип
GetServerClient в native spawner (возвращает IClient, не xrClientData).
