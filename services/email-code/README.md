# Lost Zone: подтверждение почты кодом

Сервис запускается на Google Apps Script. Игровой сервер и компьютер владельца для отправки и проверки кодов не нужны. Письма отправляются **от Google-аккаунта владельца скрипта** с именем Lost Zone. Для публичного проекта лучше использовать отдельный Google-аккаунт проекта с доступом к Firebase.

## Настройка

1. Открой https://script.google.com/home и нажми **Новый проект**. Назови его `Lost Zone Email Codes`.
2. Вставь содержимое `Code.gs` из этой папки вместо стартового кода. Сохрани.
3. Открой **Настройки проекта**. Включи **Показывать файл манифеста appsscript.json в редакторе**. В редакторе замени его содержимое файлом `appsscript.json` из этой папки.
4. В **Настройки проекта → Проект Google Cloud Platform → Изменить проект** укажи номер проекта Firebase: **925113269298**. Если Google требует настроить экран согласия OAuth, нажми **OAuth consent details → Configure consent screen → Get started**. Название — `Lost Zone Email Codes`, контактная почта — владельца, аудитория — **External**. Сохрани и вернись в Apps Script, нажми **Set project**. Приватный ключ сервисного аккаунта создавать не нужно.
5. В редакторе выбери функцию **setup** и нажми **Выполнить**. Разреши доступ к отправке писем и Firebase для своего скрипта. Владельцу нужен доступ к пользователям Firebase в проекте `lostzoneapi`. В журнале должно появиться `Setup complete`.
6. Нажми **Начать развёртывание / Deploy → Новое развёртывание → Веб-приложение**. Выполнять от имени: **Я**. Доступ: **Все / Anyone** (включая пользователей без Google-аккаунта). Разверни.
7. Скопируй **URL веб-приложения**, который заканчивается на `/exec`, и передай его для настройки игры. URL `/dev` для игроков не подходит. Открытие `/exec` в браузере должно вернуть JSON с `service: lostzone-email-code`.

После изменений кода выпусти **новую версию** текущего развёртывания, сохранив его URL.

Для постоянной работы открой **Google Auth Platform → Audience** и переведи приложение из **Testing** в **In production** кнопкой **Publish app**. В Testing разрешение тестового пользователя истекает через семь дней, поэтому оставлять почтовый сервис в этом режиме нельзя. Если пока выполняешь setup в Testing, добавь собственную почту в **Test users**. После смены статуса заново выполни setup и авторизацию, если Google их запросит. OAuth здесь разрешает доступ только владельцу сервиса; игроки не проходят этот экран и не дают скрипту доступ к своим Google-аккаунтам. [Документация об аудитории и сроке разрешений](https://support.google.com/cloud/answer/15549945?hl=en).

## Работа и ограничения

- Код содержит 6 цифр, действует 10 минут. Повторная отправка — не раньше 60 секунд.
- Не более 5 отправок и 5 неверных попыток на пользователя за часовое окно. Повторная отправка не сбрасывает счётчик неверных попыток.
- Получатель и UID берутся только из Firebase после проверки ID-токена; клиент не может назначить произвольного получателя.
- Коды хранятся как HMAC. Административный OAuth-токен и секрет остаются на стороне Google и не возвращаются клиенту.
- Только после правильного кода сервис выставляет `emailVerified` в Firebase. Игра и игровой сервер отдельно перечитывают этот флаг у Google.
- Для обычного Gmail-аккаунта Google указывает лимит **100 получателей в день**; у Google Workspace лимит выше. Лимиты могут меняться. При исчерпании квоты игра показывает ошибку, а не обходит подтверждение.
- Доставка во входящие не гарантируется. Отметка «Не спам» помогает своему почтовому ящику; собственный домен и настроенная аутентификация отправителя требуют отдельной настройки.
