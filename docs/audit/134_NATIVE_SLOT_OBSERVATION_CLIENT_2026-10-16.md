# Native client for the master slot observation

Continuation of doc132/M2b. The exception-enabled writer transport now allows `/v1/player-admission` only with a nonzero expected epoch, using the existing same-request WorldID/seed/epoch and runtime-instance headers. It retains loopback/no-proxy/no-redirect/bounded IO and private credentials confined to the worker.

`inspect_player_slot` validates native account/slot identity before constructing the URL, canonicalizes account case and obtains one read-only observation. `PlayerSlotObservation` strictly validates the compact schema/field count, exact scope/account/slot/UUID, typed nonnegative integer versions, supported ABSENT/STAGED/ACTIVE/DISCONNECTED states and bounded checkpoint revision/SHA/byte count. Absent/staged results cannot carry live versions or checkpoint data. Wrong scopes, malformed/extra fields or unsupported states refuse the observation. Failure clears its output, so a previous successful result cannot be reused accidentally. This private worker helper grants no spawn, does not claim/resume a session and does not activate gameplay persistence.

The existing actual native WinHTTP/SQLite fixture adds reads before first save, while an upload is pending, after durable Finish/replay, after disconnect and after cross-location commit. It checks canonical identity, wrong instance/world/epoch refusal, frozen-source refusal, typed checkpoint metadata and malformed replies. No mutations or extra checkpoint commits are introduced by the new reads. Compilation/execution and the complete engine build run in CI only; results are pending. Master `3b3dead23` already supplies the verified endpoint. Native admission coordinator, lease/writer lifecycle, actual NCH hydration, newest-capture barriers and world/inventory coordination remain OPEN; no live game caller is enabled.
