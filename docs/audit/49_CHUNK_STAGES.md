# 49. Чанки: 6 этапов (план на будущее, 2026-10-06)

Уточнение владельца 2026-10-07: оптимизации не должны ухудшать поведение или
частоту реакций NPC/мутантов относительно GAMMA. Предложения ниже о Reduced
ИИ 1–5 Гц/отключении баллистики являются историческим вариантом, не разрешённым
планом реализации. Сначала точное кэширование/дедупликация и безопасный scheduler
(doc 50); для офлайн мира требуется сохранение состояния и отдельная приёмка.

Сводка из doc 41 (§4, W4/W5/W8), doc 42 (§5–6) и doc 43 (разделы C, D, E, K),
плюс пожелания владельца 2026-10-06: «загруженная локация ≈ 1,5 ГБ, неактивное —
копейки», «каждый игрок прогружает только своё», «пустая локация спит».

Уровни симуляции (doc 41 §4.1):
- **Full** — рядом с игроком (до ~250 м) и бой с игроком: полный ИИ, физика.
- **Reduced** — 250–800 м и открытая видимость до 1200 м: движение и патрули,
  ИИ 1–5 Гц, без баллистики.
- **Coarse** — дальше в локации: отряд = одна запись, движение аналитически.
- **Statistical** — локации без игроков: только числа и события по расписанию.

## Этап 1. Сетка чанков и зона интереса по чанкам

Локация режется на ячейки 100×100 м, у каждой свой список объектов. Каждому
игроку сервер отбирает объекты только из ячеек вокруг него, а не перебирает
всю карту.
- Есть: сетка и индекс в «теневом» режиме, сверены фикстурами с полным
  перебором (C01–C04, C12–C13); частота по дистанции, неизменённое не
  пересылается, игроки не замедляются.
- 2026-10-06: инвентарь игрока реплицируется только ему, другим — предмет в руках (D02).
  Индекс включали по умолчанию, но с 64 игроками в одной точке кадр стал 43–48 мс
  против 21–23 мс без него (пересборка сетки каждый тик + сортировка на клиента).
  Вернули на флаг `-netcoop_chunk_index`; сначала ускорить: обновлять ячейки только
  у сдвинувшихся объектов, выборка без сортировки, ячейки клиента кэшировать.
- Приёмка: два игрока в разных концах — каждому идёт только своё, трафик на
  игрока не растёт с размером карты.

## Этап 2. Видимость сектора (PVS) и оптика

Офлайн-утилита считает для каждой ячейки, какие ячейки с неё видно по рельефу
(до 1200 м). NPC за горой остаётся дешёвым, NPC на открытом поле — живой.
Бинокль и прицел только расширяют зону, клиент не может «выключить» мир.
- Пункты: C08, D08, E21 (оптика, высоты).
- Приёмка: смотреть в бинокль на 800 м — NPC уже двигаются, никто не
  «просыпается».

## Этап 3. Менеджер LOD: Full ↔ Reduced для онлайн-NPC

Каждая ячейка получает нужный уровень по ближайшему игроку (самый высокий
спрос всех игроков). Reduced: восприятие раз в 0,5–1 с, путь из кэша, без
серверных анимаций. Повышение сразу, понижение с выдержкой (без мигания на
границе), решение по объекту, а не по ячейке.
- Есть: планировщик уровней с гистерезисом в «теневом» режиме ([lod-shadow]);
  частота ИИ по расстоянию до ближайшего игрока, бой рядом — всегда полный.
- Пункты: C05–C07, E02–E05, E08, E17.
- Приёмка: 100 NPC в Reduced < 2 мс/кадр.

## Этап 4. Прогрев и гидрация (never wake visibly)

Ячейки по направлению движения игрока прогреваются заранее (скорость ×
20–40 с): NPC поднимаются из офлайна в онлайн до того, как игрок их увидит, с
бюджетом «не больше N за кадр». Уход игрока — свёртка обратно с сохранением
всех изменений (здоровье, патроны, инвентарь), без клонов.
- 2026-10-07: PREWARM — движущийся игрок «стоит» там, где будет через 4 с
  (`-netcoop_prewarm`), ALife выводит мир впереди в онлайн заранее (16 ботов: работает);
  боевой пин — NPC в бою с игроком не уходит в офлайн до 600 м (`-netcoop_combat_pin`);
  живые NPC переживают рестарт без клонов (77/77, `run-world-living-test.ps1`).
- Пункты: E09–E11, E14–E16, E18–E19, C09–C11, D03, D10.
- Приёмка: бег/транспорт на максимальной скорости — никто не появляется
  на глазах; свёртка/развёртка не плодит дубликатов.

## Этап 5. Coarse и Statistical: офлайн-жизнь и догон времени

Далёкие и пустые части мира — компактные записи без ИИ и физики: отряды идут
по маршрутам аналитически, стычки решаются детерминированно, выброс и
логова — по расписанию. При возвращении игрока — последствия (трупы, раненые,
расход патронов), одинаковые при повторе.
- Пункты: E06–E07, E12–E13, E20, K01–K14, L23–L25.
- Приёмка: два враждебных отряда на одном маршруте, уйти на 20 минут,
  вернуться — результат боя на месте и повторяем с тем же seed.

## Этап 6. Память: «неактивное — копейки», каждый грузит своё

- Неактивные ячейки не держат онлайн-объекты (физика, модели, ИИ) — только
  офлайн-записи; цель: загруженная локация ≈ 1,5 ГБ.
- Клиент получает и держит только объекты своей зоны интереса; сервер не
  держит онлайн то, что никто не видит.
- Пустая локация спит: **сделано** — гибернация (мир сохранён, память
  отдаётся системе, Болота 1424 → 151 МБ рабочего набора, пробуждение без
  загрузки уровня).
- Общие данные только для чтения (конфиги GAMMA ~180 МБ, коллизия ~185 МБ) —
  одна копия на ПК для всех серверов локаций.
- Уже сделано по памяти: звуковой кэш 512 → 8 МБ (Болота 2,4 → 1,96 ГБ
  private), сервер без видеокарты (WARP), профайлер `-mem_profile`.
- 2026-10-07: кэш конфигов DLTX (~80 МБ) сбрасывается через минуту после уровня;
  пауза кадра сервера — пустая локация 98% → 30% ядра; профиль памяти Кордона:
  конфиги ~180 МБ, коллизия ~177 МБ, вершины скелетных моделей ~50 МБ (нужны для
  попаданий), текстур 0, геометрия рендера на сервере не грузится.
- Пункты: M02, M03, M09, плюс требования владельца 2026-10-06.

## Порядок

1 → 3 → 4 дают главное ускорение и плавность на сервере с толпой; 6 идёт
параллельно (каждый шаг сразу снижает память); 2 и 5 — после 4, потому что
им нужна гидрация.
