# 51. Стресс-проверка переходов backend (2026-10-07)

Продолжение H12: усилена проверка backend Transfers; это не приёмка hidden
spawn/release на настоящих серверах X-Ray. Тест из предыдущей незавершённой
итерации сохранён и подключается существующим unittest discovery в Actions.

Файл: backend/tests/test_transfer_stress.py.

- 1000 успешных переносов между Кордоном и Свалкой: попеременно персонаж и
  группа с NPC/мутантом. Дополнительно 250 abort с повторным prepare.
- Исключение после записи состояния и журнала на Prepare/Claim/Commit/Abort:
  транзакция полностью откатывается. Повтор команды возвращает тот же результат.
- Перезапуск Store во время переходов и повтор claim; бывший владелец не может
  менять уже переданную сущность. В конце каждого цикла одна активная сессия,
  один реестр, нет незавершённых transfer.
- Сохраняются идентичности, здоровье, ранения, деньги и индивидуальное состояние
  предметов: condition/ammo/attachments/quantity. Мёртвый член группы не переносится
  и не возрождается.
- Восемь отдельных Python процессов аварийно завершаются через os._exit до/после
  коммита каждой из четырёх стадий. База SQLite открывается заново; незакоммиченное
  откатывается, закоммиченное возвращается идемпотентно, дублей сущностей/лутa нет.

Локальный Python прогон: 2 теста PASS, 21,1 с. Нативные сборки не запускались.
CI [World Backend 37578376035](https://github.com/Gostn1ght/AnomalyMP/actions/runs/37578376035):
PASS всех 240 backend tests на Linux и Windows, включая два stress tests.
Дополнительно исправлен существующий тест admission: он проверял batch limit
64, но случайно зависел от скорости fsync и временного бюджета 1 с. В этом
тесте только scheduler clock детерминирован; production бюджеты не изменены.

H12 остаётся 🟡: эти 1000 переходов выполняются в backend, а проверка аварий
в каждой стадии на двух реальных exe и hidden target spawn остаётся отдельной
задачей. Счётчик live ✅ аудита 188 пунктов не увеличивается этим тестом.
