# NPC/мутанты без прореживания сетевых обновлений

2026-10-07. Уточнение владельца: на максимальной видимости NPC не должны
зависать или двигаться рывками; оптимизация не должна ухудшать поведение ИИ
или замедлять игроков.

В SendUpdatesAOI существовали интервалы 1/2/4/16 тиков по дистанции NPC.
При тяжёлом серверном кадре дальний интервал умножался ещё на 2/4; бюджет
16 КБ мог дополнительно отложить отправку. При кадре 110 мс 16×4 — это
номинально до 7 секунд между дальними отправками. Даже при работающем ИИ
клиенту было нечего плавно интерполировать. Игроки за 300 м также шли раз
в два тика. Это противоречит новому обязательному условию.

## Изменение

- CSE_ALifeCreatureAbstract в корне объекта (сталкеры, мутанты, акторы,
  в том числе трупы) помечает full_rate. Предметы в их руках/иерархии
  наследуют этот признак; существующая фильтрация приватного инвентаря
  остаётся на месте.
- Все такие состояния отправляются каждый тик независимо от расстояния,
  far_scale и бюджета. Дистанция не используется как граница видимости.
- Пространственный индекс включает full_rate объекты глобально каждый тик,
  в том числе за своей сферой 300 м. Иначе исправление работало бы только
  при выключенном индексе.
- Hash equality/500 мс keep-alive не подавляет full_rate состояния. Потеря
  одного пакета не вызывает дополнительного ожидания keep-alive; также
  исчезают hash/lookup расходы этой ветки. Доставка остаётся unreliable.
- Для прочих мировых предметов прежние tiers/budget/unchanged suppression
  сохраняются. Частота обновления самой логики NPC, количество населения,
  movement/vision/physics алгоритмы не меняются.

## Проверка и ограничения

Фактический native cadence извлекается fixture из xrServer.cpp; прямые
assert требуют every=1 и обход бюджета для full_rate записей. Тест проверяет
все дистанционные границы, глобальные candidates на каждом из 64 тиков
при overload 1/2/4, сравнение полного сканирования и индекса с 512 full-rate
объектами в наборе 12 000 записей, порядок, reuse handles и fallback.
Сборка/выполнение native только GitHub Actions. Локально — Python AST/diff.

Проверки и полная комбинированная DX11 сборка ожидаются. Предыдущая сборка
37584887087 (только direct tickets) заменяется новой для этого исправления.

Это устранение конкретного искусственного источника задержек, не обещание
плавности при перегруженном сервере или недостаточном канале. Нужно измерить
трафик/очередь отправки, реальные 16/64+ игроков, NPC на максимальной видимости,
потери/задержку сети, p50/p95 сервера и клиента. Трафик для дальних персонажей
увеличится; гарантировать его прежний объём было бы нечестно. CPU необходимо
снижать без возврата прореживания персонажей. Сам кадр сервера 110 мс,
клиентская анимация, AI cadence и отсутствие зависаний требуют живой приёмки.
Новые live ✅ в аудит 188 этапов не добавлены.
