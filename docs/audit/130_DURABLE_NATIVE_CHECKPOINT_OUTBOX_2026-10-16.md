# Durable native checkpoint outbox — M2b subtask

Private worker implementation `netcoop_checkpoint_outbox.h` connects the existing immutable NCH snapshot transport to a bounded filesystem journal. It does not activate master-primary gameplay persistence; admission/hydration, writable location/session lifecycle and inventory/world/quest coordination remain required.

## Persistence and recovery

One private dedicated local directory, held open against rename, and an exclusive process lock. The index binds world/seed/master epoch/location/writer instance; no credential or endpoint secret is serialized. Immutable snapshot files use random128-bit transaction names, are completely written and flushed before atomic index publication. The small index contains queue metadata, bound upload cursors and generation highwater; it is flushed and replaced with write-through rename. An upload step rewrites only this bounded index, not the entire NCH image. IO is worker-only; no engine/Lua objects cross this boundary.

Admission is locally durable only after both snapshot and index succeed. Count32 and aggregate64MiB snapshot limits include completed-but-unconsumed jobs. Each NCH image is at most20MiB; index at most1MiB, persistent highwater at most5120 character identities. Accepted snapshots are owned independently of producer memory. Each character's queue follows increasing capture generations and consecutive expected entity/save versions under the same location/session fence and slot. Different characters may be advanced separately for fair scheduling; the caller still owns lease renewals/backoff. No authority/version refusal discards or rebases queued data.

After an acknowledged HTTP step, cursor publication must succeed before the queue exposes progress/completion. Failed index replacement restores the previous cursor, so a retry uses the same command ID. Recovery verifies every referenced image, size/SHA and cursor binding before cleanup or HTTP. Even a disk phase3 cursor is restored as Finish-pending: only a fresh master acknowledgement under current authority exposes its generation-tagged receipt. A hard process death after master Finish and before cursor publication therefore replays that same Finish instead of creating another save.

Only the first job of a character may advance or be retired. Explicit retirement requires that exact generation's fresh durable receipt and atomically removes the entry before deleting its queue copy. Retirement must follow the coordinator's consumption/persistence of that receipt. Generation highwater survives retirement/restart, rejecting older/repeated captures; `accepted_generation` lets the coordinator seed its counter. `latest_accepted` describes the highest **admitted** generation, not a gameplay handoff barrier: the coordinator must also freeze/check its newest captured generation and coordinate all related inventory/world mutations.

Startup removes only bounded, unreferenced, exactly named outbox copies and an unfinished index candidate, after validating all retained jobs and directory entries. Missing index beside snapshots, corruption, unknown files, reparse points and hardlinked files fail closed without deleting queued data. The same-epoch/instance restriction intentionally refuses automatic takeover/replay after a master restart; explicit fenced reconciliation remains M2b work.

## Verification

The existing actual C++/WinHTTP fixture is extended in its already configured CI step. It will enqueue three generations, hard-kill a child process after actual SQLite Finish but before local cursor persistence, reopen/replay without duplicates, preserve FIFO and generation highwater, refuse stale scope, require fresh proof after another restart and read exact newest NCH bytes. Real Windows file locks force admission/progress/retirement publication failures. Filesystem cases cover Unicode/space paths, exclusive process lock, mutation of producer memory, corruption/missing index preservation, orphan cleanup, unrelated files, hardlink refusal and actual count/64MiB admission limits. Compilation and runtime verification are pending GitHub Actions; no local native compile, game or location server is used.

The installed verified release remains native/master97ae0069c with patch000020 until the new full CI succeeds. No private installed save, account, world or configuration has been modified for this source batch.
