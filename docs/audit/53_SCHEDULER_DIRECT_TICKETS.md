# Прямые проверки жизненного цикла планировщика

Дата: 2026-10-07. Продолжение адаптации IX-Ray из документа 50.

В версии 3a95c0dce каждый `active(item)` искал указатель в hash map. На обычном
пути это повторялось после Needed, Scale и Update; у realtime — до и после
Needed. В новой версии запись очереди содержит непрозрачный 64-битный билет:
32 бита индекса слота и 32 бита поколения. Проверка читает слот напрямую,
сверяет поколение и указатель, не обращаясь к самому объекту. Hash map остаётся
для регистрации/отмены и публичных проверок, а не для горячего цикла.

Освобождённые слоты переиспользуются через free list. Отмена не выделяет память.
При исчерпании поколения слот навсегда выводится из обращения: старое задание
не оживает после переполнения. Нет параллельного доступа к живым объектам ИИ.

Частота, приоритет, порядок, dt, интервал и бюджет обновлений не сокращаются.
Оригинальные heap/callback/budget алгоритмы сохранены. Нет ограничения
численности NPC/мутантов, дистанционного пропуска ИИ или замедления игроков.

## Проверка

`scripts/check-netcoop-scheduler.py` компилирует фактический код только в GitHub
Actions. Помимо IX-Ray reference используется точный hash-check baseline
3a95c0dcedee3be79ac012b10c8e399a281f66df из `scripts/fixtures/hash-scheduler`.
Host теперь использует реальный engine robin_hood::unordered_node_map, а не
std::unordered_map. Импортируется фактический profiler.h.

- Точное сравнение 32 825 callback: dt, время, порядок, бюджет и интервалы.
- Существующие удаления себя/другого объекта в Needed/Scale/Update, reuse
  адресов, stable RT cancellation/order, register-pair differential.
- Прямые билеты: недействительные значения, старые поколения, 100 000
  переиспользований, рост до 4096 слотов, free-list bounded reuse, исчерпание
  поколения через uint8 fixture и retirement вместо wrap.
- Устаревший deferred EnsureOrder после уничтожения/замены адреса; повторная
  регистрация обычного объекта после Needed=false.
- Отдельный release microbenchmark без sanitizers: фактические старый/новый
  планировщики, 10 000 кадров, 7 чередующихся прогонов, медиана; 16/128,
  64/128, 128/512 и 64/0 realtime/normal объектов. Подготовка и разрушение
  исключены из времени; число callbacks обязано совпасть.

Локально проверены только Python AST, project/filter XML и идентичность
baseline исходников. Native fixture, benchmark и полная DX11 сборка: ожидают
GitHub Actions. Заранее ускорение кадра игры не заявляется.

## Обязательная игровая приёмка

Владелец дополнительно подтвердил: игрок не должен видеть зависших или
дёргающихся NPC на максимальной дистанции видимости. Приёмка требует реальных
exe на сервере: те же население, GAMMA AI и дистанция, 16/64+ игроков;
p50/p95 кадра, CPU/память, движение/наведение/реакции дальних и ближних NPC,
отсутствие новых пауз и рывков. Сохранение cadence в fixture не доказывает
плавность анимаций/репликации или достаточную производительность под нагрузкой.
При регрессии правку необходимо исправить или откатить; нельзя компенсировать
снижением частоты ИИ/репликации, видимости или количества NPC.

Microbenchmark измеряет накладные расходы планировщика, а не Lua/планировщики
действий, зрение, сетевую интерполяцию или полный серверный кадр ~110 мс.
Live64 acceptance остаётся открытым; в аудит 188 пунктов новые ✅ не добавлены.
