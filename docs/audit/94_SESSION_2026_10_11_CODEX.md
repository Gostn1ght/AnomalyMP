## Звук и голос

Лог релиза владельца: `Can't create source: Out of Memory` на старте,
затем `Max targets - 256`. Пул пытался создать 1024 источника и занимал
весь доступный лимит. Теперь учитывает mono/stereo budget контекста и
оставляет 32 источника для голосовых потоков/записей.

Голосовые контакты выделяют источник только после прихода аудио, освобождают
его после полного проигрывания очереди. Неудачное/частичное выделение
освобождает каждый созданный buffer/source; ранее handles терялись при
ошибке. Перед сменой OpenAL context голос освобождает старые handles,
сохраняя объекты игроков, на которые ссылается игровой код.

Проверки: `check-netcoop-voice.py`, `check-netcoop-lua-scope.py` PASS;
`check-native-voice-resources.py` добавлена в DX11 CI (1000 повторных
ошибок source/buffer, частичное выделение, очистка, повторный запуск,
смена context). Нативные проверки локально не выполнялись.

## Убранное оружие

Раньше Activate(NO_ACTIVE_SLOT) ждал окончания hide animation, затем код
переноса очищал слот. Update больше не мог найти ActiveItem() для завершения
очистки, особенно при переносе на пояс/в другой слот и выбросе. Теперь
`netcoop_remove_from_hands` до удаления ссылки явно переключает HUD предмет
в hidden, снимает zoom и очищает соответствующие active/next/previous slots.
Если уже запланирован другой слот, он сохраняется. Путь действует только
для netcoop акторов; NPC/freeplay продолжают штатный путь.
Убранное неактивное оружие без zoom не сбрасывает оптику текущего оружия.

`check-native-inventory-hands.py` в CI: actual helper, все четыре вызова до
очистки слота, устройства без оружия, повторный вызов, другой pending slot,
NPC/freeplay. Игровая проверка остаётся нужна.

## Остаток работы

Дополнительное исправление границы доверия: `GE_WPN_STATE_CHANGE` раньше
попадал в default allow. Теперь проверяется владелец предмета и полный размер

(как в item reports); ammo/next-ammo
indexes сверяются с типами оружия (нож не может создать патроны). Cursor
пакета восстанавливается после peek. Actual native fixture добавлена в DX11 CI.

Это не закрывает магазин: его протокол требует отдельного изменения
подтверждений shot/reload и сверки predicted ammo владельца. Простое
игнорирование клиентского count без изменения reload сломает дробовики,
боеприпасы разных типов и магазины гранатомётов. Дополнительно выявлен второй
писатель состояния: периодические item reports принимают predicted ammo/stack
владельца и могут перезаписать серверный результат shot/reload. Полное исправление
должно согласовать оба канала, расход коробок, unload и full snapshots с
подтверждениями команд. README пункт остаётся ⬜.
