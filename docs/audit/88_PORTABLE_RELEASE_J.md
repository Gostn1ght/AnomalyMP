Owner: two separate portable folders on J: — the game for players and a complete

check disk, archive compatibility and no dependency on C:; no server secrets in

## Layout decisions (from engine source, not guessed)

- CLocatorAPI::Register: a later registration overrides; fsgame lines are
  processed in order and loose $game_data$ last. GAMMA data packs go to
  db\lostzone, a new line after $arch_dir_addons$ -> same priority as today
  (GAMMA loose over every Anomaly archive).
- Archive header entry_point = $fs_root$\gamedata\ (the else branch maps via
  the $fs_root$ alias); volumes are named .db0-.db9 then .dba-.dbf (ProcessOne
  accepts any ".db*" extension).
- The engine's implicit $fs_root$ (fsgame's folder via generic_string) uses '/'
  separators; instead each launcher writes fsgame from a template with
  $fs_root$ = the folder it runs from (ANSI, no BOM; tested with spaces and
  Cyrillic in the path). Templates: scripts\dist\fsgame_*.template, generated by
  tools\make-portable-fsgame.py from the owner's working fsgame files.
- Configs/scripts stay loose: GAMMA mods (dxml_core, bas laser, ubgl_no_3db,
  canted irons) read/write files in $game_config$ with io.open; packing them
  would break those mods.
- Server without textures: CTexture::Load returns before reading images on a
  dedicated server (2026-10-06 change), so texture archives are omitted there.
- Players get no -dbg (it registers run_string/jump_to_level/g_god console
  commands); the server keeps the watchdog's arguments.

## Packing (xrCompress from engine-src\compressor, run from J:\LostZone\_work
## through junctions to the runtime gamedata; outputs land on J:)

- lz_misc (-strong): 158 MB -> 56.6 MB, 6179 files, 1458 aliased duplicates.
- lz_meshes (-strong): 18.6 GB -> 13.18 GB in 13 volumes, ~4 h.
- lz_levels (-strong), lz_sounds and lz_textures (-fast: DDS/OGG are stored;
  -strong on 36.7 GB of DDS would have taken ~14 h for little gain).
- Protection: standard compressed .db archives, no loose assets. This is NOT
  encryption — community tools unpack .db. The engine loader has no encrypted
  archive support (no trivial_encryptor/xdb path in LocatorAPI); real
  encryption needs a loader + packer change built in GHA, and any client-held
  key can be extracted. Not promised.
