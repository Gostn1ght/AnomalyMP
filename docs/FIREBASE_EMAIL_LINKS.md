# Lost Zone: подтверждение почты по ссылке

Рабочий клиент использует штатные письма Firebase Authentication. Google Apps Script и разрешения владельца на отправку почты для этого режима не нужны. Файлы `services/email-code` сохраняются как прежняя реализация кодов; рабочая регистрация их не вызывает.

1. Игрок регистрируется в меню: почта, имя аккаунта, пароль.
2. Клиент вызывает Firebase `sendOobCode` с `requestType: VERIFY_EMAIL` и ID-токеном созданного аккаунта. Получателя определяет Firebase.
3. Игрок открывает ссылку из письма на странице Firebase и возвращается в игру.
4. Экран ожидания раз в пять секунд обновляет ID-токен и перечитывает `emailVerified` у Google. Подтверждение открывает следующий этап автоматически; без подтверждения окно регистрации остаётся открытым. При сетевой ошибке следующая попытка выполняется через 20 секунд.
5. При недоставленном письме аккаунт и защищённый refresh-токен сохраняются. Кнопка повторной отправки не создаёт второй аккаунт.
6. «Ввёл не ту почту» позволяет указать другой адрес для того же аккаунта. `VERIFY_AND_CHANGE_EMAIL` подтверждает новый адрес перед заменой и совместим с защитой Firebase от перебора адресов. Ожидающий адрес сохраняется в защищённом локальном файле. Подтверждение старого адреса не завершает подтверждение нового.
7. До создания аккаунта проверяются формат адреса и почтовые записи DNS домена: MX, запрет Null MX и резерв A/AAAA согласно RFC 5321. Отсутствие домена просит исправить адрес; временная ошибка DNS предлагает повторить позже. Наличие конкретного ящика подтверждается ссылкой: успешная отправка письма сама по себе этого не доказывает.
8. Поля поддерживают Ctrl+V, выделение Ctrl+A и замену выделенного текста. Unicode из буфера переводится в CP1251; вставка ограничена размером поля, управляющие символы заменяются пробелами.

Сохранённое значение `emailVerified` не разрешает вход само по себе: перед переходом клиент делает свежую проверку, а игровой сервер независимо проверяет Firebase-учётную запись.

Настройка имени отправителя, темы и текста письма доступна в Firebase Console → Authentication → Templates → Email address verification. Стандартная страница Firebase обрабатывает ссылку; собственный обработчик и домен не требуются.

Проверки: `scripts/check-netcoop-menu.py` выполняет рабочий Lua-сценарий с UI-заглушками; `scripts/check-firebase-links.py` компилирует в GitHub Actions фактический C++ worker/вход запроса с подменой HTTPS и проверяет регистрацию, доставку, повторную отправку, ошибки, свежесть подтверждения и блокировку повторных запросов. Эти проверки не отправляют настоящие письма и не создают пользователей.

Документация: [Firebase Auth REST API — Send email verification](https://firebase.google.com/docs/reference/rest/auth#section-send-email-verification).

Исправление почты выполняется одним запросом: пользователь вводит правильный адрес и пароль регистрации. Клиент делает свежий `signInWithPassword` с текущим адресом аккаунта (даже если в нём опечатка), проверяет неизменность UID и отправляет `VERIFY_AND_CHANGE_EMAIL` на правильный адрес. Истёкший refresh-токен не препятствует этому входу. Новый адрес остаётся на экране при ошибках; фоновая проверка не заменяет форму во время редактирования. Пароль очищается до публикации завершения native-запроса и не записывается в локальный файл. Ошибки Firebase с пояснениями после кода обрабатываются по коду.
